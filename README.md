# 3D 아틀라스 — 서울 · 제주 · 채플힐

OpenStreetMap 벡터타일 + SRTM 표고로 만든 인터랙티브 미니어처. Three.js 직접 렌더.

```
python3 -m http.server 8747
```

- 서울 → http://localhost:8747/
- 제주 → http://localhost:8747/?city=jeju
- 채플힐(NC) → http://localhost:8747/?city=chapelhill

오른쪽 위 **i → 도시 선택**에서도 전환할 수 있다.

## 구성

| 파일 | 역할 |
|---|---|
| `tools/build-city.mjs` | z14 벡터타일 → 경량 씬 데이터 (도시마다 한 번만 실행) |
| `app.js` | 지형·건물·나무·물·바다·도로 렌더 |
| `landmarks.js` | 도시별 랜드마크 캐리커쳐 (서울 13 · 제주 13 · 채플힐 9) |
| `index.html` | UI, 이름표 오버레이, `?city=` 분기 |
| `test/screenshot.mjs` | 정적 서버 + Playwright 스크린샷 (시각 검증용) |

## 데이터 만들기

```
npm i
node tools/build-city.mjs seoul
node tools/build-city.mjs jeju
node tools/build-city.mjs chapelhill
```

## 피복

`landcover` · `park` · `landuse` 세 레이어를 종류별로 갈라 `greens`에 `{ t, r }`로 담는다.

| `t` | 뜻 | 출처 | 바닥 | 나무 |
|---|---|---|---|---|
| 0 | 잔디·초지 | `landcover` class=grass | ○ | |
| 1 | 숲 | `landcover` class=wood | ○ | ○ |
| 2 | 골프장 | `landcover` subclass=golf_course | ○ | |
| 3 | 밭·과수원 | `landcover` class=farmland | ○ | |
| 4 | 부지 | `landuse` 묘지·학교·테마파크·운동장 등 | ○ | |
| 5 | 공원·국립공원 | `park` | | ○ |

골프장은 class가 grass라 잔디와 섞이는데, 제주에서는 세 번째로 넓은 피복이라 색을 따로 준다.
공원은 숲 폴리곤과 통째로 겹치므로 바닥을 깔지 않는다 — 깔면 둘이 깊이 경합한다.

나무만으로는 숲이 땅으로 읽히지 않는다. 바닥을 함께 깔아야 나무 밀도를 낮춰도 숲이 남는다.

## 다른 도시

`tools/build-city.mjs`의 `CITIES`에 중심좌표와 bbox를 넣고, `landmarks.js`의
`LANDMARKS_BY_CITY`에 랜드마크 목록과 빌더를 더한다. `index.html` 상단 `CITY`에는 화면 문구와
첫 시점만 적는다. 타일과 표고는 전 세계 커버.

`CITIES`의 선택 필드 — 기본값으로 두면 서울과 같이 동작한다.

| 필드 | 뜻 | 기본 | 제주 |
|---|---|---|---|
| `unit` | bin 좌표 1단위의 미터 | 1 | 2 |
| `tree` | 나무 격자 간격(m) | 34 | 68 |
| `hRef` | 지형 색 램프가 끝 색에 닿는 표고(m) | 420 | 460 |
| `gLo` | 램프에서 건너뛸 앞쪽 색 수 | 0 | 1 |
| `bRef` | 건물 색 램프가 끝 색에 닿는 높이(m) | 165 | 60 |

랜드마크는 `s: [가로, 세로]` 배율(기본 `[1.7, 2.6]`), `foot`(이 반경의 지형 최저점에 앉힌다),
`cam: [거리, 올려본각]`, `clear`(이 반경 안의 건물·나무를 지운다)로 조절한다.

## 알아둘 것

- 지형·건물 높이 3× 과장 (`EXAG`)
- 안개·시야·그림자 범위는 도시 폭에 비례해 늘어난다 (서울 = 1, 제주 = 1.82)
- UI는 `?city=`로만 갈린다. 랜드마크 목록은 오른쪽, 접을 수 있다
- **좌표 단위** — bin은 Int16이라 ±32.7km가 한계다. 폭 79km인 제주는 `unit: 2`로 저장한다
- **물** — DEM(30m)으로는 강바닥이 뭉개져 물이 묻히므로, 물 폴리곤을 마스크로 구워 그 아래
  지형을 파낸다. 바다(`class: ocean`)는 따로 모아 마스크에만 쓰고, 화면에는 수평선까지 이어진
  해수면 한 장을 편다 — 타일마다 쪼개진 폴리곤을 그대로 그리면 경계에서 z-fighting이 난다
- **섬의 가장자리** — 지형은 벡터타일 범위보다 10% 넓게 받는다. 그 여유분에는 바다 폴리곤이
  없어 해발 0m 땅으로 남으므로, 섬이면 타일 범위 밖을 통째로 바다로 친다
- **깊이 경합** — 시야가 580km까지 열리면 58km 지점의 깊이 분해능이 근평면 20에서 약 10m밖에
  안 된다. 해수면 판(y=2)과 그 위 1~13단위에 놓인 항·포구 폴리곤이 통째로 깜박였다. 셋으로 막는다.
  ① 해발 4m 미만 물 폴리곤은 그리지 않는다 — 해수면 판이 이미 같은 색으로 덮는다
  ② 해수면 아래 지형은 16m가 아니라 90m를 판다 — 해안선이 해수면 높이를 얕게 스치지 않도록
  ③ 근평면을 `20 × 축척²`로 민다 (서울 20 그대로, 제주 66)
  `test/flicker.mjs` + `test/coastdiff.py`로 카메라를 6m 흔들어 해안대 변화율을 잰다 (8.35% → 2.43%)
- 첫 로드는 표고 타일 + 데이터로 서울 약 10초, 제주 약 20초 (DEM z12 타일 96장)

### 제주 데이터의 한계

- OSM 건물 커버리지가 성기다. 제주시 도심은 z14 타일 한 장에 2,600동이 들어 있지만 한림읍은
  35동뿐이다. 서귀포·중산간은 실제보다 한산하게 보인다
- **중산간이 비어 보이는 건 OSM에 피복 데이터가 없기 때문이다.** 섬 전역 43개 육지 타일
  (179km²)을 훑으면 타일에 든 피복은 전부 합쳐 73.8km²(41%)뿐이다. 세 레이어를 모두 읽어도
  나머지 59%는 채울 것이 없다 — 제주 중산간의 목장·밭은 아직 아무도 그려 넣지 않았다
- DEM은 z12(약 38m/px), 지형 메시는 세그먼트당 약 109m다. 한라산은 제대로 읽히지만 지름
  200~300m인 오름은 거의 남지 않는다

## 미니어처 표현

- 지형·건물·랜드마크는 `miniature.js`의 공통 무광 재질을 사용한다. 수면만 거칠기를 낮춰 유약 같은 빛을 낸다.
- 낮 팔레트는 크림·세이지·청록으로 제한하고, 나무는 둥근 수관과 원뿔 수관을 인스턴싱으로 섞는다.
- 물가 테두리는 합쳐진 수면 마스크 양쪽을 검사해 타일 경계를 제외한다. 서울의 수면을 가로지르는 주요 도로에는 모형식 상판·난간·교각을 더한다. 원본 데이터에 교량 속성이 없어 실제 다리 구조를 복원하는 방식은 아니다.
- 장면에만 약한 틸트 시프트 효과를 적용한다. 중앙은 선명하고 근접 시 효과가 사라지며, UI와 이름표는 흐려지지 않는다.
- 그림자는 넓게 퍼지는 PCF 필터와 낮은 그림자 강도를 사용한다. 후처리는 `miniature.js`, 도시 팔레트와 조명은 `app.js`에서 조절한다.

### 랜드마크 모형

서울 13개 모형에 전망대 창호, 타워 입면, 문루 아치·곡선 처마, 국회의사당 열주, 경기장 관람석·지붕 등 특징을 추가했다. 작은 부품은 재질별로 병합해 그린다. 장소 선택 시 실제 모형 경계와 화면 비율을 기준으로 카메라 거리를 계산하고 모형 중앙을 바라본다.

`http://localhost:8747/test/landmark-gallery.html`에서 모형을 따로 확인할 수 있다. `?city=jeju`는 제주 모형 검수용이다. GPU를 사용할 수 있는 macOS에서는 `CITY_TEST_GPU=metal node test/screenshot.mjs ...`로 캡처할 수 있다.

### 작은 도시 장면과 이동 조작

`city-life.js`는 광화문 앞 모형식 광장(포장·벤치·분수·가로등), 한강 유람선 2척, 교량 경로 위 차량 최대 24대, 일부 건물의 박공지붕·옥상 정원·옥탑, 야간 창문 조명을 만든다. 건물 디테일은 인스턴싱하고 가로등의 빛 번짐은 점 스프라이트를 사용한다. 배는 수면 마스크 안의 경로, 차량은 도로 상판과 같은 좌표를 따라 움직인다. 실제 운항·교통 정보나 광장 시설 배치를 재현하는 기능은 아니다. 모션 줄이기 설정에서는 배와 차량이 정지한다.

마우스: 왼쪽 드래그는 회전, **Space 또는 Shift를 누른 채 왼쪽 드래그**와 오른쪽 드래그는 이동, 휠은 확대·축소다. Space 해제 또는 창 포커스 상실 시 회전 조작으로 돌아간다.

지도 위에서 왼쪽 버튼을 같은 자리(6px 허용)에서 **1초간 누르면 임시 이동 모드**가 켜진다. 누른 채 바로 드래그해도 이동하며, 커서는 `grab`/`grabbing`으로 바뀐다. 이동 드래그 중 움직이거나 드래그를 마칠 때마다 3초 타이머를 갱신하고, 3초간 이동하지 않으면 회전 모드로 복귀한다. Space 이동은 독립적으로 유지하며 창 포커스 상실·포인터 취소 시 임시 모드를 해제한다. `pan-gesture.js`가 제스처와 타이머를 관리하고 `MapControls.setMouseGesture`가 누르고 있는 OrbitControls 제스처를 전환한다. Three.js 버전을 올릴 때 내부 state/초기화 메서드 호환성을 확인해야 한다. `CITY_TEST_GPU=metal node test/pan-gesture.mjs`로 길게 누르기·이동·자동 복귀·기존 키 조작을 검증한다.

오른쪽 아래 나침반은 카메라 회전에 맞춰 N·E·S·W 방향을 표시한다. 클릭하거나 키보드로 선택 후 Enter를 누르면 현재 중심·거리·기울기를 유지한 채 북쪽을 위로 맞춘다. 자동 비행은 중단한다. `compass.js`가 방향 표시와 550ms 회전을 처리하며, 모션 줄이기 설정에서는 즉시 맞춘다. `CITY_TEST_GPU=metal node test/compass.mjs`로 방향·시점 보존·키보드·모바일·야간을 검증한다.

아이폰 Safari에서 **기울여 보기**를 누르고 동작·방향 센서 접근을 허용하면 현재 자세를 기준으로 시점이 움직인다. 좌우 최대 30°, 상하 최대 18°로 제한하고 작은 손떨림은 완화한다. 이 모드에서는 한 손가락 드래그로 이동하고 두 손가락으로 확대·축소한다. 나침반 위 **이동** 버튼을 누른 동안 좌우 기울임은 화면 기준 좌우 이동, 상하 기울임은 확대·축소로 작동한다. 아래로 기울이면 확대, 위로 기울이면 축소한다. 누르는 순간의 자세가 기준이며 손을 떼면 즉시 멈추고 현재 시점을 유지한 채 둘러보기로 돌아온다. 터치 이동·자동 비행·나침반 조작을 우선하며, 화면 방향이 바뀌면 현재 시점에서 다시 기준을 잡는다. 버튼을 다시 누르거나 탭을 백그라운드로 보내면 모드를 종료한다.

센서 사용에는 **HTTPS 접속**이 필요하다. PC의 개발 서버를 아이폰에서 `http://192.168.…:8747`로 여는 것만으로는 사용할 수 없다. 화면을 가리는 센서 안내 팝업은 표시하지 않으며 상태는 버튼의 접근성 이름과 툴팁에 기록한다. 브라우저 자체의 센서 권한 요청은 필요하다. `device-look.js`가 센서와 카메라 연동을 담당한다. `CITY_TEST_GPU=metal node test/device-look.mjs`는 모의 센서로 권한 처리, 시점 제한, 터치 이동·확대, 재설정, 화면 회전, 나침반 연동과 모바일 UI를 검증한다. 실제 아이폰 하드웨어에서의 감도와 권한 동작은 별도로 확인해야 한다.

개발 서버 실행 후 `CITY_TEST_GPU=metal node test/city-life.mjs`로 낮/밤 재생성, 서울·제주 장면, 이동 애니메이션, 실제 Space 드래그·키 해제·포커스 상실 동작을 검증한다.

### 즉각적인 이동과 드래그 품질

`map-controls.js`는 고정된 Three.js 0.185.1의 OrbitControls에서 누적 이동량만 즉시 적용한다. 회전 감속은 유지하며 Space/Shift/오른쪽 드래그에 같은 규칙이 적용된다. `_panOffset` 내부 필드를 사용하므로 Three.js 버전을 올릴 때 `test/controls-response.mjs` 검증이 필요하다.

조작 중에는 픽셀 비율을 최대 1로 낮추고 초점 후처리를 생략하며 그림자 위치를 고정한다. 조작 종료 120ms 후 기존 해상도·후처리를 복원하고 필요한 그림자를 갱신한다. 사용자 조작이 시작되면 진행 중이던 카메라 비행도 중단한다.

개발 서버 실행 후 `CITY_TEST_GPU=metal node test/controls-response.mjs`로 세 이동 방식의 즉각 반영·잔류 이동 없음, 회전 감속, 그림자 고정, 화질 복원을 확인한다.

### 확대 시 주변 장소 이름표

`neighborhood-labels.js`는 카메라가 가까워질수록 산·주요 공원·대학, 역·시장·문화시설, 작은 공원·명소 순서로 주변 이름표를 추가한다. 이름표를 누르면 해당 장소로 이동하고 장소 종류와 좌표를 표시한다. 기존 이름표 버튼으로 함께 켜고 끈다.

서울 5,667개, 제주 1,084개, 채플힐 516개의 POI를 포함한다. 기본 데이터는 지도와 동일한 OpenFreeMap / OpenStreetMap 2026-08-30 스냅샷에서 추출했다. OSM에 수록된 장소 기준이며 실시간 정보나 모든 시설을 포함하지 않는다. 데이터 재생성은 `node tools/build-pois.mjs seoul|jeju|chapelhill`에서 원하는 도시 하나를 인자로 넣어 실행한다.

호텔은 가까운 확대 단계(거리 2,600 이하), 백화점은 중간 확대 단계(4,600 이하)에서 나타난다. 분류는 OSM 태그 기준이다. 제주의 해수욕장 9곳은 벡터타일 POI에 이름이 없어 제주관광공사 [Visit Jeju](https://www.visitjeju.net/)의 이름·지도 좌표로 보완했다. 각 원문 링크는 `data/jeju.beaches.json`에 보존한다. `node tools/build-jeju-beaches.mjs` 실행 후 제주 POI를 재생성하면 갱신된다.

로컬 JSON을 한 번 읽고 공간 격자로 주변 후보를 찾는다. 이름표는 UI와 서로의 영역을 피해 데스크톱 최대 20개, 모바일 최대 9개만 표시한다. 배치 계산은 120ms 간격이며 표시 중인 이름표 위치는 매 프레임 갱신한다. POI 로드가 실패해도 기존 랜드마크는 표시한다.

개발 서버 실행 후 `CITY_TEST_GPU=metal node test/neighborhood-labels.mjs`로 확대 단계, 이름표 겹침, 선택·이동, 밤 테마, 표시 토글, 동네 전환, 모바일 표시 수, 제주 POI를 검증한다.

### 노스캐롤라이나 채플힐

UNC 캠퍼스·프랭클린 스트리트·인접 카보로를 포함한 약 13.5×14.5km 범위를 담는다. 북쪽 경계를 35.995°까지 넓혀 Eubanks Road와 모리스그로브 학교를 포함한다. z14 타일 64개에서 건물 27,804동과 숲·도로·수계를 생성했으며, 지형 타일을 제외한 저장 데이터는 약 2.03MB다. 올드 웰, 모어헤드–패터슨 종탑, 윌슨 도서관, 모어헤드 천문관은 흰 열주·벽돌·돔을 강조한 모형이다. 위치는 OSM POI와 [Old Well 좌표](https://www.wikidata.org/wiki/Q7085397)를 참고했다. 서경 좌표는 W로 표시한다.

`CITY_TEST_GPU=metal node test/cities-and-pois.mjs`로 채플힐 모형·장소 선택·야간·모바일 도시 전환, 제주 해수욕장·호텔 확대 단계, 서울 백화점 클릭을 확인한다.

채플힐에서는 학교 28곳, 마트 21곳과 카페·음식점·약국·편의점·가게도 표시한다. 학교·마트는 중간 확대, 소규모 가게는 가까운 확대 단계에서 나타난다. 모리스그로브 초등학교는 정식 랜드마크이며, 오른쪽 ‘동네 둘러보기’에는 Chapel Watch Village와 해리스티터 채플힐 노스 바로가기가 있다. Chapel Watch Village는 [단지 공식 지도](https://chapelwatchvillage.com/neighborhood/)의 공용 위치로 보완하며, 원본은 `data/chapelhill.places.json`에 기록한다. 특정 개인의 거주지 정보는 포함하지 않는다.


채플힐 랜드마크에 The Farm 테니스 클럽, Ballet School of Chapel Hill, Chapel Hill Public Library, Dean Smith Center·Koury Natatorium을 추가했다. 테니스 코트·클럽하우스, 스튜디오 창과 바, 도서관의 유리 입면·차양, 낮은 돔과 수영·다이빙 풀을 표현한다. 쿠리 수영장은 내부가 보이도록 지붕을 생략한 모형이며 실제 개방형 수영장이 아니다. 실측 복원이 아니라 장소의 특징을 강조한 미니어처다.

위치·시설 확인: [The Farm 공식 안내](https://uncfarm.org/the-farm/contact-us/), [The Farm 지도 좌표](https://maps.roadtrippers.com/us/chapel-hill-nc/sports/the-farm-at-unc), [발레스쿨 공식 안내](https://www.balletschoolofchapelhill.com/), [발레스쿨 OSM 위치](https://mapcarta.com/W44325853), [공공도서관 설계](https://www.ramsa.com/expertise/project/chapel-hill-public-library), [다이빙 클럽 시설 안내](https://ncdivingclub.com/content/facility), [쿠리 수영장 위치](https://mapcarta.com/26734478). 공공도서관 좌표는 기존 OSM POI와 동일하다.

모리스그로브 초등학교는 OSM의 학교 위치에 낮은 벽돌 교실동, 창, 푸른 입구 차양, 작은 운동장을 단순화한 모형을 둔다. 랜드마크로 승격해 일반 POI 이름표는 중복 표시하지 않는다. The Farm 모형 중심은 OSM 테니스 코트 군집(-79.00565, 35.89368)에 맞춰 진입로와 겹치지 않도록 잡았다. 목록이 길어지면 내부 스크롤하며 나침반 공간을 남긴다.

### 한반도 개괄 지도

`http://localhost:8747/?city=korea` 또는 i 버튼의 ‘한반도’로 연다. 남북한 육지 범위를 합친 지형 모형에 도시 18곳, 강·하천 31개, 산·봉우리 21곳을 표시한다. 강은 파란 이름표, 산은 초록 이름표로 구분하며, 전체 보기에는 대표 이름만, 확대하면 지류와 더 많은 산 이름이 나타난다. 도시 이름을 누르면 주변 지형으로 이동하며, 서울·제주의 ↗ 이름표는 해당 상세 미니어처 지도로 연결한다. 자동 비행은 한반도 화면 안에서만 이동한다. 회전·이동·나침반·기울여 보기와 낮/노을/밤을 지원한다. 실제 휴대폰 센서는 HTTPS가 필요하므로 일반 LAN HTTP 접속에서는 터치로 확인한다.

`peninsula.js`는 도시의 건물·나무·실시간 DEM 타일을 로드하지 않는다. `data/korea.terrain.bin`은 769×1254 Int16 고도 격자(1,928,652 bytes, 약 1.84 MiB)이며 `data/korea.json` 및 `data/korea.features.json`과 합쳐 약 1.96 MiB다. 약 900m 격자의 지형을 육지 내부에서 가볍게 평활화(약 600m 가우시안)한 뒤 높이를 8배로 강조한다. 한반도에서는 초점 흐림 후처리를 생략해 능선과 해안을 선명하게 유지한다. 200m 이하 저지대는 높이 변화를 더 완만하게 압축한다. 원본 고도는 보존하고, 화면의 산·물길·이름표는 동일한 가공 표면을 따른다. 저지대의 청회색에서 산지의 녹색·황토색, 높은 곳의 밝은색으로 이어지는 8개 고도 기준점을 쓴다. 색은 식생이나 적설 분포가 아닌 고도를 나타내며, 밝은 받침면과 부드러운 그림자로 입체 모형을 표현한다. 작은 섬·해안·물길은 축척에 따라 생략되며, 북쪽 가장자리는 원본 육지 자료의 범위를 따른다. 국경선·행정 경계는 표시하지 않는다. 상세 도시 데이터는 해당 도시로 전환할 때 읽는다.

재생성은 `python3 tools/build-korea.py`로 한다(Pillow·numpy 필요). [Natural Earth](https://www.naturalearthdata.com/) 1:10m의 육지 범위·도시·하천과 [AWS/Mapzen Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) z8 지형 타일 66장을 사용한다. 다운로드는 OS 임시 폴더의 `korea-atlas-build`에 캐시하고, 모든 타일을 받은 경우에만 결과를 저장한다. 도시 좌표는 Natural Earth의 대표점이며 건물 위치를 의미하지 않는다.

`CITY_TEST_GPU=metal node test/korea.mjs`는 지형 데이터 용량, 외부 타일 요청 없음, 렌더링 복잡도, 모바일 이름표, 도시 선택, 지역 확대·자동 비행·테마 전환과 서울 상세 지도 연결을 검증한다. GitHub Pages에서도 사용할 수 있다.

강·산 자료는 `node tools/build-korea-features.mjs`로 재생성한다. OpenFreeMap의 2026-08-30 스냅샷에서 z9 타일 240개의 OSM waterway/mountain_peak 레이어를 읽는다. 북한산 백운대는 같은 스냅샷의 기존 서울 z14 POI 좌표로 보완한다. 타일 경계의 강줄기 중복을 잘라내고 연결된 끝점만 이어 약 220m 허용 오차로 단순화한다. 저수지 등 원본에서 선이 끊긴 곳은 임의로 연결하지 않는다. 강줄기 52개 조각을 31개 이름으로 묶으며, 산은 이름이 같은 봉우리를 지역 범위로 구분한다. OSM 자료의 라이선스는 ODbL이며 `data/korea.features.json`에 출처를 기록했다. 이름표를 눌러 해당 지형으로 이동할 수 있고, 도시·강·산 각 분류에 표시 공간을 배분한다.

한반도 하단 **인구밀도** 버튼으로 지형 위 3D 기둥을 켜고 끌 수 있다. [WorldPop Global2](https://www.worldpop.org/blog/worldpop-global2-global-high-resolution-population-estimates-for-2015-2030/) R2025A v1 constrained의 **2025년 남북한 UN 보정 추정 인구**를 사용하며 모델 추정 분포를 보여준다. 원자료는 30초각 인구수 GeoTIFF이고, 이를 픽셀 중심 기준 0.05°(약 4–5.6km) 격자로 합산한다. 위도별 구면 면적으로 나눠 **명/km²**를 계산한다. 분모는 해안의 바다까지 포함한 전체 격자 면적이며, 거주지 면적당 밀도가 아니다. NoData는 인구를 더하지 않고 두 국가의 유효 인구 총합은 집계 전후 보존된다. 지형과 자료 해안선 해상도 차이로 작은 해안 격자가 바다에 걸칠 수 있다.

기둥은 지형 표면에서 시작하고 높이는 인구밀도에 정비례한다. 모든 기둥에 고정 높이 계수 3.5(명/km²당 화면 지형 단위)를 적용해 밀도가 2배면 지형 위부터의 막대 높이도 2배다. 각 기둥은 밝은 밑면에서 진한 꼭대기로 연속 그라데이션을 적용한다. 꼭대기 색은 0 / 1,000 / 5,000 / 10,000 / 15,000 / 25,000명 이상에 해당하며, 크림·노랑·주황·산호색·빨강·짙은 빨강로 밀도가 높은 도시 사이의 차이를 구분한다. 옆면은 공통 높이 척도에서의 등가 밀도(기둥 밀도 × 상대 높이) 색을 사용한다. 0명인 격자는 표시하지 않는다. `population.js`는 9,281개 기둥을 단일 InstancedMesh로 렌더링한다. `data/korea.population.json`(223,316 bytes)은 처음 켤 때만 불러오고 이후 재사용한다. 낮·밤 전환에도 상태를 유지한다. [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)이며 출처 URL과 계산 방식은 데이터 메타데이터에 포함한다. 재생성: `python3 tools/build-korea-population.py` (numpy/Pillow). 검증: `node test/population.mjs` (macOS Metal; 2025년 자료·축소 높이·그라데이션 렌더링·토글·지연 로딩·테마·모바일·실패 후 재시도).

인구밀도를 켜면 지도 이름표는 도시 지명만 표시한다. 도시 대표점에서 7.5km 이내의 인구 기둥 중 가장 높은 기둥 상단에 이름표를 배치하고, 겹치는 이름표는 화면 크기에 따라 조정·생략한다. 끄면 원래 지형 위 위치와 산·강 이름표를 복원한다.


### 2025년 주간 강수량

한반도 하단 **주간강수** 버튼은 남한의 2km 강수 격자를 지형 위 파란 기둥으로 표시한다. 높이는 주간 누적 강수량(mm)에 정비례하며, 모든 주에 같은 계수(1mm당 화면 지형 단위 120)를 적용한다. 밝은 밑면에서 진한 파랑으로 이어지는 색도 공통 척도(0·10·30·100·300·600mm)를 사용한다. 600mm를 넘어도 높이는 계속 증가한다. 인구밀도와 전환하며 비교할 수 있다. 슬라이더·이전/다음·재생으로 주를 바꾸고, 처음에는 전국 평균 강수량이 가장 큰 주를 보여준다.

자료는 [기상청 AWS 객관분석 API](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=248)의 `rn_day`, `obj=mq`, `map=D3`, `grid=2`다. 관측소 강수량을 공간 분석한 격자이며 각 격자의 직접 관측값은 아니다. WGS84 Lambert 정각원추 투영(표준 위도 30°·60°, 원점 38°N 126°E)을 사용하며 서울·부산·제주 관측소의 공식 격자 좌표와 대조했다. 일 누적량은 다음 날 00:00 KST(동일 시각인 당일 24:00도 재시도에 사용)에서 읽고, 누적값을 중복 합산하지 않는다. 월요일–일요일로 합산해 53개 구간을 만들며 첫 구간은 1월 1–5일, 마지막은 12월 29–31일이다. 짧은 구간은 UI에 일수를 표시한다.

Natural Earth 남한 육지 마스크 안의 24,711개 격자만 저장한다. 하루라도 결측인 셀의 해당 주는 결측으로 유지하고 북한·결측·0mm에는 막대를 만들지 않는다. 작은 해안·섬은 육지 마스크 해상도의 영향을 받는다. 0.1mm 단위 uint16 시계열 약 2.62MB, 격자 인덱스 약 0.10MB와 메타데이터를 처음 켤 때만 읽는다. API 키나 기상청 실시간 요청은 브라우저에 포함하지 않는다.

재생성: `python3 tools/build-korea-rain.py` (numpy/Pillow 필요). API 이용 신청 후 `~/.env`의 `kma_api` 또는 환경 변수 `KMA_API_KEY`로 인증한다. 인증키는 curl 표준입력으로만 전달하며 일별 자료는 OS 임시 폴더의 `korea-rain-build`에 캐시한다. 검증: `node test/rainfall.mjs` (macOS Metal; 날짜·투영·선형 높이·재생·테마·인구밀도 전환·실패 재시도·모바일·로드 중 닫기).


강수량 패널의 연도 메뉴에서 2025년과 2026년을 전환한다. 연도별 자료는 처음 선택할 때만 읽고, 선택했던 주를 기억한다. 지도 막대는 연도에 관계없이 동일한 mm 높이·색 척도를 사용한다. 상단 차트는 남한 유효 격자의 주간 누적 강수량 평균이며 선택한 주와 값을 강조한다. 월 눈금은 해당 연도의 수집 범위까지만 표시하고, 수집 종료일을 패널에 명시한다. 올해 자료 갱신은 `python3 tools/build-korea-rain.py --year 2026`으로 실행한다. 기본적으로 한국 시간 어제까지의 완결된 일 자료를 수집하며, `--end YYYY-MM-DD`로 종료일을 제한할 수 있다. 파일은 연도별로 분리하여 2025년 자료를 보존한다.

2026년 현재 수록 범위는 **1월 1일–10월 4일, 277일·40개 주간 구간**이다. 연도별 추가 파일은 약 1.98MB이며 격자 인덱스는 2025년과 공유한다. 실시간 자동 갱신이 아닌 로컬에서 생성한 스냅샷이다.

### 겨울 적설 — 2025년 11월부터 2026년 3월

하단 **강수·적설** 패널의 지표 메뉴에서 **쌓인 눈 · 주 평균**과 **24시간 적설 증가 · 주 최대**를 선택한다. 남한 2km 격자의 매일 **09:00 KST** 표본을 월요일–일요일로 묶는다. 첫째·마지막 구간은 겨울 기간 안의 날짜만 포함한다. 첫 모드는 `sd_tot`의 주간 표본 평균, 둘째 모드는 `sd_24h`의 양수 부분에 대한 주간 표본 최댓값이다. 연속시간 평균·최댓값이나 새로 내린 눈의 총량을 의미하지 않는다. 슬라이더의 11·12·1·2·3월 눈금, 평균 차트, 재생을 지원하며 두 적설 모드 사이에서는 같은 주를 유지한다. 그래프는 각 격자의 주간 값들을 남한 유효 격자에 대해 평균한 값이다.

[기상청 AWS 객관분석](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=248) 웹 표의 `sd_24hr`는 시험 요청에서 관측소 0개와 육지 마스크 같은 응답을 반환했다. 이를 실제 적설로 사용하지 않는다. 공식 [관측변수 코드표](https://apihub.kma.go.kr/getAttachFile.do?fileName=sfc_obs_list.pdf)의 작동 코드 `sd_24h`는 **적설 − 하루 전 적설**로 설명되어 있으므로 UI에 ‘24시간 적설 증가’로 명시한다. 깊이 변화에는 융해·침하 등의 영향이 포함된다.

단위는 cm이며, 막대는 지형 위에서 **1cm당 화면 지형 단위 1,200**으로 선형 증가한다. 두 적설 모드는 같은 척도와 흰색·청록색·짙은 청록색 범례(0·1·5·10·30·60cm 이상)를 쓴다. 강수량 mm와는 다른 높이 계수다. KMA의 MQ 공간 분석에서 물리적으로 불가능한 음의 적설 깊이는 0으로, 24시간 음의 변화는 ‘증가 없음’으로 처리한다. -99.90 및 -999 계열 결측은 0으로 채우지 않고, 하루라도 결측인 격자는 해당 주를 결측으로 유지한다. 격자 분석값은 개별 관측소 실측값과 다를 수 있다.

재생성: `PYTHONDONTWRITEBYTECODE=1 python3 tools/build-korea-snow.py`. 기존 `~/.env` 키를 읽으며, 매일 09시 두 변수의 302개 요청 결과를 OS 임시 폴더 `korea-snow-build`에 캐시한다. 자료는 `data/korea.snow.2025-26.mean.*` 및 `data/korea.snow.2025-26.max.*`에 별도로 저장하고 강수량 격자 인덱스를 공유한다. 브라우저는 적설을 처음 선택할 때만 로컬 파일을 읽는다. 검증: `node test/snow.mjs`.

### 고속철도 시간표 시뮬레이션

`http://localhost:8747/?city=korea&rail=1` 또는 한반도 하단 **고속철도** 버튼으로 시작한다. 요일, 한국 시간 00–24시, 재생/일시정지, 60·120·600·1800배속, 경부·호남·강릉선 필터를 제공한다. 운행 중 열차 목록에서 선택하면 다음 정차역과 시각을 확인하고 해당 위치로 확대할 수 있다. 요일이 바뀌는 자정 이후에는 전날 출발편도 이전 요일 조건으로 처리한다. 재생 시 다음 요일로 넘어가며, 탭이 숨겨지면 시간을 진행시키지 않는다. 인구·날씨와는 상호 배타적으로 표시하고 테마 변경 시 선택 시각과 재생 상태를 유지한다.

출처는 [코레일 KTX 시간표, 2026-10-01 기준 XLSX](https://www.korail.com/file/cubedata/COMMON/jfile/202609/23/202609231a0cb38a2c5200.xlsx). 요일 조건을 포함한 352개 운행 항목(경부 205, 호남 97, 강릉 50)을 저장했다. 전체 요일 합계이며 하루 운행 수는 다르다. 수서 출발편을 포함한다. 수원·구포·서대전 경유 및 동해행 82개 항목은 제외했고, 경전·전라·중앙·동해·중부내륙 시트는 이번 범위에 포함하지 않는다. 특정 날짜의 임시·휴일 변경이나 운행 취소는 반영하지 않는다. 병결 열차도 시간표의 열차번호별로 계산하므로 화면 개수는 실제 물리적 편성 수와 다를 수 있다.

**실시간 위치가 아니다.** 역 좌표는 개략 앵커이고 선로는 역을 연결한 도식이다. 공개된 역 시각 사이에 거리 비례 등속 보간을 적용하며 정차 시간·가감속·지연·실제 곡선과 터널은 재현하지 않는다. 지형과 열차는 시인성을 위해 과장했다. 서원주 좌표는 위키백과 역 좌표, 만종은 기존 OpenFreeMap 2026-08-30 스냅샷의 station POI로 교정했다. `data/korea.rail.json`에 출처, 시간표 시트에 대응하는 노선, 원본 행 번호, 제외 항목과 범위를 기록했다. 파일은 약 113KB이며 최초 토글 때만 요청한다. 외부 API 인증키를 사용하지 않는다.

재생성: `python3 tools/build-korea-rail.py [원본.xlsx]` (`openpyxl` 필요). 인수를 생략하면 OS 임시 폴더에 원본을 내려받는다. 원본의 일부 역방향 편이 하행 표에 실린 경우 역 시각 순서로 방향을 판별한다. 검증: `node test/rail.mjs` (macOS Metal/Playwright). 날짜 조건·자정 넘김, 자료 지연 로드, 시각·배속·열차 선택, 테마 보존, 레이어 전환과 모바일 배치를 검사한다. GitHub Pages에서도 사용할 수 있다.

### 도시 지표 밀착·암반·서울역 방향 보정

숲 경계점만 삼각화하던 면은 산골짜기 위로 떠서 나무를 가릴 수 있었다. 이제 `surface-cover.js`가 피복 폴리곤과 내부 구멍을 약 20–30m 텍스처로 만들고 **지형과 동일한 정점·삼각형**에 얹는다. 나무 밑동도 표시 지형 삼각형의 높이를 보간하므로 숲 면 아래로 묻히지 않는다. 기하를 추가 세분화하지 않아 지형보다 더 촘촘한 격자를 만들지는 않는다. 피복 텍스처는 테마 변경 때 해제한다.

`node tools/build-seoul-surfaces.mjs`는 기존 OpenFreeMap 2026-08-30 스냅샷의 서울 z14 타일 374개에서 전체 landcover 링을 복원한다. `data/seoul.surfaces.json`에 숲·초지·농지·골프장과 `rock`/`bare_rock` 1,158개 폴리곤 조각(중복된 타일 경계 조각 포함)을 저장한다. 암반은 회색 계열이며 해당 픽셀의 나무는 렌더링하지 않는다. 경사만으로 암반을 추정하지 않고 OSM 피복 분류를 따른다. © OpenStreetMap contributors / ODbL. 다른 도시를 새로 빌드할 때도 `build-city.mjs`가 암반과 내부 구멍을 보존한다.

서울역 캐리커처는 [문화역서울284 OSM 외곽선](https://www.openstreetmap.org/way/759569673)에 맞춰 긴 축을 남북으로 90도 회전하고 중심을 옛 역사 위치로 옮겼다. 정면은 동쪽 광장 방향이다. 테스트: `node test/seoul-surfaces.mjs` — 지형 정점 일치, 내부 구멍과 암반 우선순위, 역사 긴 축, 테마 변경 시 텍스처 해제 및 관악산·북한산·서울역 화면을 확인한다.

서울 이름표는 먼 시야에서도 주요 산(북한산·관악산·도봉산·남산 등)을 우선 표시한다. 약 9km 이상 시야에서는 같은 산의 여러 봉우리를 가장 높은 대표 지점 하나로 묶어 산 이름만 보여주고, 가까워지면 원래 봉우리 이름으로 돌아간다. 7.5km 이상에서는 구 이름, 14.5km 이내에서는 동네 이름을 후보로 넣고 화면 겹침을 피해서 배치한다. 주요 공원과 대학도 일반 상점보다 먼저 보이며 호텔 등 세부 POI의 기존 확대 조건은 유지한다. 지명은 `node tools/build-seoul-places.mjs`가 `build-seoul-surfaces.mjs`의 OSM 타일 캐시에서 재생성한다. `data/seoul.places.json` 약 90KB, 구·동 및 동네 675개(서울 지도 범위의 인접 지역 포함). 검증: `node test/seoul-labels.mjs`.

### 한반도 농경지 — 인구밀도와 함께 보기

하단 **농경지** 버튼을 인구밀도와 독립적으로 켜고 끈다. 바로 비교: `http://localhost:8747/?city=korea&cropland=1&population=1`. 지면의 황색이 진할수록 해당 격자의 농경지 비율이 높다. 지형 정점과 동일한 표면에 표시하고 인구밀도 계산·분모·막대 높이·개수는 변경하지 않는다. 산지·농경지를 제외한 면적이나 도시 개발 가능 면적을 산출하는 기능은 아니다. 두 시점의 공간 분포를 비교하는 용도이며 농경지는 2021년, 인구는 2025년 자료다.

[ESA WorldCover 2021 v200](https://esa-worldcover.org/en/data-access)의 **class 40 Cropland**를 사용한다. 이는 1년 내 수확 가능한 초본 작물(논·밭 중심)의 위성 분류다. 다년생 목본 작물은 수목·관목 분류, 온실은 시가화 분류에 들어가므로 농업용 토지 전체와 같지 않다. [자료 DOI](https://doi.org/10.5281/zenodo.7254221), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 필수 출처: © ESA WorldCover project 2021 / Contains modified Copernicus Sentinel data (2021) processed by ESA WorldCover consortium.

`tools/build-korea-cropland.py`는 3° COG 타일 11개를 OS 임시 폴더 `korea-cropland`에 캐시한다. 원본 해상도의 60×60 픽셀에서 농경지 픽셀을 세어 전체 3,600개로 나누고, 0.005°(동서 약 400–470m, 남북 약 556m) 격자 비율을 정수 %로 저장한다. 범주형 COG 미리보기나 색상 이미지에서 비율을 추정하지 않는다. 결측 픽셀이 하나라도 있으면 해당 집계 셀을 결측 처리한다. Natural Earth 남북한 경계로 자른 뒤 한반도 모형의 Mercator 평면에 최근접 재표본화한다. 현 지형이 바다로 처리하는 곳은 숨긴다. 따라서 거친 해안선이나 간척지 일부는 농경지 원자료가 있어도 표시되지 않을 수 있다. 분모는 해안·물 등을 포함한 격자 전체이며 실제 필지 경계나 정확한 농지 면적 통계로 사용하지 않는다.

웹 파일은 `data/korea.cropland.json`과 `data/korea.cropland.png`(1536×2507, 단일 채널, 0–100%, 255=결측/범위 밖)이며 합계 약 **0.53MB**, 최초 활성화 때만 요청한다. 유효 집계 셀은 918,661개다. 원자료의 상세 출처·집계 방식·투영·범위는 JSON에 기록했다. 재생성에는 Python의 `rasterio`, `numpy`, `Pillow`가 필요하다. 이번 환경에서는 `/tmp/seoul-landcover-venv/bin/python3 tools/build-korea-cropland.py`로 실행했다. 검증: `node test/cropland.mjs`, `node test/cropland-loading.mjs`. 실제 원본 셀 비율과 Mercator 정렬, 인구 동시 표시, 레이어 지연 로드/재사용/실패 재시도, 로드 중 닫기, 테마 전환과 텍스처 해제, 모바일 배치를 확인했다.

인구밀도 지역 이름표: 전체 화면(카메라 거리 900km 이상)의 기존 대표 도시 표시를 유지하고, 확대하면 OSM 도시·읍·마을 지명을 추가한다. 마을 후보는 350km 이내에서 나타난다. 화면에 실제 투영되는 후보들 중 인구밀도가 높은 격자를 우선하고, 데스크톱 24개·모바일 12개 상한과 충돌 회피를 유지한다. 지명 위치가 속한 약 5km 인구 격자 위에 이름표를 붙이고 한 셀의 여러 이름은 대표 하나만 사용한다. 도시 행정구역 평균 밀도를 뜻하지 않는다. 막대의 밀도·높이·색 척도는 재조정하지 않는다. 이름표를 누르면 한반도 지도 안에서 해당 지역으로 확대하며, 전체 화면으로 돌아가거나 인구 모드를 끄면 추가 이름표는 숨긴다.

지역 지명은 `node tools/build-korea-population-places.mjs`로 기존 한반도 OSM z9 캐시에서 재생성한다. `data/korea.population-places.json`은 도시·읍·마을 2,237개, 약 193KiB이며 인구 자료 활성화 시 함께 로드한다. 모형의 남북한 육지 마스크로 범위를 제한하며, OSM 누락과 거친 해안·국경 마스크의 한계가 있다. © OpenStreetMap contributors / ODbL, OpenFreeMap 2026-08-30 스냅샷. 검증: `node test/population.mjs`, `node test/population-regions.mjs`.
